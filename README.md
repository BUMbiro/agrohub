## 🌾 АгроХаб – интернет-магазин сельхозпродукции

**АгроХаб** – это учебный интернет-магазин на **Django**, созданный для закрепления навыков веб-разработки.  
Проект включает каталог товаров (семена, удобрения, агрохимикаты, инструменты, техника, саженцы), новости фермеров и 
форму обратной связи.

---

## 🚀 Основной функционал

- **Категории товаров** – семена, удобрения, агрохимикаты, садовый инвентарь, электроинструменты, мини-техника, 
системы орошения, саженцы.
- **Список товаров на главной** – цикл по всем товарам с эмодзи-иконками, ценой и обрезанным до 100 символов описанием.
- **Список товаров в каждой категории** – с эмодзи-иконками, ценой и единицей измерения (кг, л, м, шт.).
- **Детальная страница товара** – открывается по URL `/products/<pk>/`, показывает изображение, категорию, описание, 
цену, наличие.
- **Форма добавления товара** – пользователь может добавить новый товар через веб-форму с валидацией полей.
- **Пагинация на главной** – постраничный вывод товаров (по 6 штук на страницу).
- **Новости фермеров** – приземлённые новости из жизни агробизнеса с датами по сезонам.
- **Контакты** – форма обратной связи с выводом данных в консоль и карта Астрахани. Данные организации 
подтягиваются из модели `Contact` (заполняется через админку).
- **Админка Django** – управление товарами, категориями, новостями и контактами. Настроены списки, фильтры и поиск.
- **Кастомная команда `load_test_data`** – очищает БД и загружает тестовые данные из фикстур.
- **Вывод последних 5 продуктов в консоль** при загрузке главной страницы (для отладки).
- **Динамическое меню категорий** – категории в выпадающем меню берутся из БД (через контекстный процессор).
- **Адаптивная вёрстка** на Bootstrap 5 с зелёной темой.

## 🛠 Технологический стек

- **Python 3.12** – язык программирования.
- **Django 6.1.1** – веб-фреймворк.
- **PostgreSQL 17** – база данных (через `psycopg2-binary`).
- **python-dotenv** – чтение настроек из `.env` (в зависимостях).
- **Bootstrap 5** – стилизация и адаптивность.
- **Эмодзи** – для иконок товаров (работают без внешних библиотек).
- **Pillow** – работа с изображениями (ImageField в моделях).
- **IPython** – удобная оболочка для `manage.py shell`.

## 📦 Установка и запуск

### 1. Клонируйте репозиторий:

```bash
git clone https://github.com/BUMbiro/agrohub.git
cd agrohub
```
### 2. Создайте и активируйте виртуальное окружение:
```bash
python -m venv .venv
.venv\Scripts\activate      # Windows
# source .venv/bin/activate  # macOS/Linux
```
### 3. Установите зависимости:
```bash
pip install -r requirements.txt
```
### 4. Создайте базу данных PostgreSQL
В `psql` под суперпользователем `postgres`:

```sql
CREATE USER agrohub_user WITH PASSWORD 'ваш_пароль';
ALTER USER agrohub_user CREATEDB;
CREATE DATABASE agrohub WITH OWNER = agrohub_user ENCODING = 'UTF8';
```
### 5. Настройте переменные окружения
Скопируйте .env.template в .env и заполните своими значениями:

```bash
cp .env.template .env    # Windows: copy .env.template .env
```
Пример содержимого `.env`:

```env
SECRET_KEY=ваш_секретный_ключ
DEBUG=True

DB_NAME=agrohub
DB_USER=agrohub_user
DB_PASSWORD=ваш_пароль
DB_HOST=localhost
DB_PORT=5432
```
>`.env` добавлен в `.gitignore` — реальные пароли в репозиторий не попадают.
>В `.env.template` только заглушки.

### 6. Выполните миграции базы данных:
```bash
python manage.py migrate
```
### 7. Создайте суперпользователя для доступа в админку:
```bash
python manage.py createsuperuser
```
### 8. Наполните базу тестовыми данными
**Есть два способа.**

**Способ А** — кастомная команда (рекомендуется):

```bash
python manage.py load_test_data
```
Команда удалит старые данные и загрузит категории и продукты из фикстур `catalog/fixtures/`.

**Способ Б** — вручную через loaddata:

```bash
python manage.py loaddata catalog/fixtures/categories.json
python manage.py loaddata catalog/fixtures/products.json
```
### 9. Запустите сервер:
```bash
python manage.py runserver
```
Откройте браузер по адресу:

## 👉 http://127.0.0.1:8000/

## 🗄 Модели
- `Category – name, slug, description.` Описывает категорию товаров.

- `Product – category (FK → Category), name, slug, description, price, unit,
image, in_stock, created_at, updated_at.` Товар в каталоге.

- `News – title, content, date, image.` Новости фермеров на главной.

- `Contact – name, address, phone, email.` Контактные данные магазина.

Для всех моделей заданы `Meta (verbose_name, verbose_name_plural)` и метод `__str__`.

---

## 🔗 Основные маршруты

- `/` (имя `home`) — главная: товары с пагинацией + новости
- `/category/<slug>/` (имя `category_detail`) — товары в категории
- `/products/<int:pk>/` (имя `product_detail`) — детальная страница товара
- `/products/create/` (имя `product_create`) — форма добавления товара
- `/contacts/` (имя `contacts`) — контакты с формой обратной связи
- `/admin/` — админка Django

---

## 🧪 Проверка работы форм

### Форма обратной связи (`/contacts/`)
При отправке заполненных данных они выводятся в консоль сервера, а пользователь видит сообщение об успешной отправке.

Пример вывода в консоли: 

`Имя: Иван, Email: ivan@mail.ru, Сообщение: Здравствуйте!`

### Форма добавления товара (`/products/create/`)
Поля обязательны (кроме изображения), есть валидация:
- цена должна быть больше нуля
- название — не короче 2 символов

Slug генерируется автоматически из названия. После сохранения пользователь перенаправляется на страницу нового товара.

## 📌 Планы по доработке (для портфолио)

### Крупные фичи
- **Корзина покупок** – добавление товаров, изменение количества, удаление.
- **Оформление заказов** – форма оформления, история заказов в личном кабинете.
- **Авторизация и личный кабинет** – регистрация, вход, профиль, история заказов.

### Улучшения каталога
- **Фильтры и сортировка на главной** – по категории, цене, дате, наличию.
- **Поиск по каталогу** – по названию и описанию с подсветкой совпадений.
- **Избранное** – добавление товаров в список желаний.

### Технические улучшения
- **Загрузка реальных изображений товаров** – сейчас у большинства товаров эмодзи-заглушки.
- **Оптимизация запросов** – `select_related` и `prefetch_related` для пагинации и связей.
- **Unit-тесты** – покрытие основных сценариев (модели, views, формы).

### Инфраструктура
- **Docker** – контейнеризация проекта для быстрого развёртывания.
- **CI/CD** – автозапуск тестов и проверок при push.
- **Деплой** – выложить проект на реальный хостинг (например, PythonAnywhere или VPS).
