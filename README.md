## 🌾 АгроХаб – интернет-магазин сельхозпродукции

**АгроХаб** – это учебный интернет-магазин на **Django**, созданный для закрепления навыков веб-разработки.  
Проект включает каталог товаров (семена, удобрения, агрохимикаты, инструменты, техника, саженцы), блог 
с агрономическими статьями, новости фермеров и форму обратной связи.

---

## 🚀 Основной функционал

- **Категории товаров** – семена, удобрения, агрохимикаты, садовый инвентарь, электроинструменты, мини-техника, 
системы орошения, саженцы.
- **Список товаров на главной** – цикл по всем товарам с эмодзи-иконками, ценой и обрезанным до 100 символов описанием.
- **Детальная страница товара** – открывается по URL `/products/<pk>/`, показывает изображение, категорию, описание, 
цену, наличие.
- **Полный CRUD для товаров** – создание, просмотр, редактирование, удаление через веб-формы.
  - Кнопки «Редактировать» и «Удалить» на детальной странице товара.
  - Страница подтверждения удаления с названием товара.
- **Форма товара** – общая для создания и редактирования, с валидацией (см. раздел «Валидация формы товара»).
- **Пагинация на главной** – постраничный вывод товаров (по 6 на страницу).
- **Новости фермеров** – приземлённые новости из жизни агробизнеса с датами по сезонам.
- **Контакты** – форма обратной связи с выводом данных в консоль и карта Астрахани. Данные организации 
подтягиваются из модели `Contact`.
- **Блог** – раздел со статьями:
  - Список статей (только опубликованные, с пагинацией).
  - Детальная страница со счётчиком просмотров.
  - Полный CRUD через веб-формы: создание, редактирование, удаление.
  - При достижении 100 просмотров — поздравительное письмо (консольный backend).
- **Админка Django** – управление товарами, категориями, новостями, контактами и статьями блога. 
Настроены списки, фильтры и поиск.
- **Кастомная команда `load_test_data`** – очищает БД и загружает тестовые данные из фикстур.
- **Динамическое меню категорий** – категории в меню берутся из БД через контекстный процессор.
- **Адаптивная вёрстка** на Bootstrap 5 с зелёной темой.

## 🛠 Технологический стек

- **Python 3.12** – язык программирования.
- **Django 6.1.1** – веб-фреймворк.
- **PostgreSQL 17** – база данных (через `psycopg2-binary`).
- **python-dotenv** – чтение настроек из `.env` (в зависимостях).
- **Bootstrap 5** – стилизация и адаптивность.
- **Эмодзи** – для иконок товаров.
- **Pillow** – работа с изображениями.
- **IPython** – удобная оболочка для `manage.py shell`.
- **django.forms** – формы, валидация и стилизация.
- **CBV (Class-Based Views)** – контроллеры на классах (ListView, DetailView, CreateView, UpdateView, DeleteView).
- **django.core.mail** – отправка писем (в dev-режиме — консольный backend).

## 📦 Установка и запуск

### 1. Клонируйте репозиторий:

```bash
git clone https://github.com/BUMbiro/agrohub.git
cd agrohub
```
### 2. Создайте и активируйте виртуальное окружение:
```bash
python -m venv .venv
.venv\Scripts\activate      # Windows
# source .venv/bin/activate  # macOS/Linux
```
### 3. Установите зависимости:
```bash
pip install -r requirements.txt
```
### 4. Создайте базу данных PostgreSQL
В `psql` под суперпользователем `postgres`:

```sql
CREATE USER agrohub_user WITH PASSWORD 'ваш_пароль';
ALTER USER agrohub_user CREATEDB;
CREATE DATABASE agrohub WITH OWNER = agrohub_user ENCODING = 'UTF8';
```
### 5. Настройте переменные окружения
Скопируйте .env.template в .env и заполните своими значениями:

```bash
cp .env.template .env    # Windows: copy .env.template .env
```
Пример содержимого `.env`:

```env
SECRET_KEY=ваш_секретный_ключ
DEBUG=True

DB_NAME=agrohub
DB_USER=agrohub_user
DB_PASSWORD=ваш_пароль
DB_HOST=localhost
DB_PORT=5432
```
>`.env` добавлен в `.gitignore` — реальные пароли в репозиторий не попадают.
>В `.env.template` только заглушки.

### 6. Выполните миграции базы данных:
```bash
python manage.py migrate
```
### 7. Создайте суперпользователя для доступа в админку:
```bash
python manage.py createsuperuser
```
### 8. Наполните базу тестовыми данными
**Есть два способа.**

**Способ А** — кастомная команда (рекомендуется):

```bash
python manage.py load_test_data
```
Команда удалит старые данные и загрузит категории и продукты из фикстур `catalog/fixtures/`.

**Способ Б** — вручную через loaddata:

```bash
python manage.py loaddata catalog/fixtures/categories.json
python manage.py loaddata catalog/fixtures/products.json
```
### 9. Запустите сервер:
```bash
python manage.py runserver
```
Откройте браузер по адресу:

## 👉 http://127.0.0.1:8000/

## 🗄 Модели

**Каталог**
- `Category – name, slug, description.` Описывает категорию товаров.

- `Product – category (FK → Category), name, slug, description, price, unit,
image, in_stock, created_at, updated_at.` Товар в каталоге.

- `News – title, content, date, image.` Новости фермеров на главной.

- `Contact – name, address, phone, email.` Контактные данные магазина.

**Блог**

- BlogPost – title, content, preview, created_at, updated_at, is_published, views.

Для всех моделей заданы Meta (verbose_name, verbose_name_plural) и метод __str__.

## 🔗 Основные маршруты

**Каталог (catalog):**

- / (имя catalog:home) — главная: товары с пагинацией + новости

- /category/<slug>/ (имя catalog:category_detail) — товары в категории

- /products/create/ (имя catalog:product_create) — форма добавления товара

- /products/<int:pk>/ (имя catalog:product_detail) — детальная страница товара

- /products/<int:pk>/update/ (имя catalog:product_update) — редактирование товара

- /products/<int:pk>/delete/ (имя catalog:product_delete) — удаление товара

- /contacts/ (имя catalog:contacts) — контакты

**Блог (blog):**

- /blogs/ (имя blog:blogpost_list) — список статей

- /blogs/create/ (имя blog:blogpost_create) — создание статьи

- /blogs/<int:pk>/ (имя blog:blogpost_detail) — детальная страница статьи

- /blogs/<int:pk>/update/ (имя blog:blogpost_update) — редактирование

- /blogs/<int:pk>/delete/ (имя blog:blogpost_delete) — удаление

**Админка:**

- /admin/ — админка Django

## 🧪 Проверка работы форм

### Форма обратной связи (`/contacts/`)
При отправке заполненных данных они выводятся в консоль сервера, а пользователь видит сообщение об успешной отправке.

Пример вывода в консоли: 

`Имя: Иван, Email: ivan@mail.ru, Сообщение: Здравствуйте!`

### Форма товара (`/products/create/` и `/products/<pk>/update/`)
Одна форма используется и для создания, и для редактирования. Поля обязательны (кроме изображения).

Валидация:
- **Запрещённые слова** в названии и описании (казино, криптовалюта, крипта, биржа, дешево, бесплатно, обман, полиция, 
радар) — регистр игнорируется.
- **Цена** не может быть отрицательной.
- **Изображение** — только JPEG или PNG, размер не более 5 МБ.

Slug генерируется автоматически из названия. После создания — редирект на страницу нового товара, 
после редактирования — на страницу отредактированного.

### Формы блога (`/blogs/create/`, `/blogs/<pk>/update/`)
Валидация: заголовок ≥ 3 символов. После редактирования — редирект на страницу статьи.

## ✅ Валидация формы товара

`ProductForm` проверяет:

- **Запрещённые слова** в названии и описании: казино, криптовалюта, крипта, биржа, дешево, бесплатно, обман, полиция, радар. Регистр игнорируется.
- **Цена** не может быть отрицательной.
- **Изображение** — только формата JPEG или PNG, размер не более 5 МБ.

Список запрещённых слов вынесен в константу `FORBIDDEN_WORDS` в `catalog/forms.py`.

Все поля формы стилизованы под Bootstrap через метод `__init__`.

## 📧 Email в dev-режиме
Для отправки писем используется консольный backend:

```python
EMAIL_BACKEND = 'django.core.mail.backends.console.EmailBackend'
```
Письма не отправляются реально, а печатаются в консоль runserver. Это стандартный backend Django для разработки.
Для продакшена замените на `smtp.EmailBackend` и укажите **SMTP**-настройки в `.env`.

При достижении статьёй 100 просмотров отправляется поздравительное письмо.
